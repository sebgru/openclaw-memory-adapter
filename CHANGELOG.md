# Changelog

## 1.14.0

- Add disabled-by-default native memory routing (`nativeRouting`). When enabled, `unified_memory_search` (scopes `all`/`main`) and the prompt hook search curated memory and notes (optionally session transcripts) through OpenClaw's native memory provider lease, called with the turn's own session authority and host-minted memory audience. Documents, archive and outputs/projects stay on the external service; identifier-like queries run both lanes and keep the service's exact hits.
- With routing on, the prompt hook no longer runs a service `scope=all` search on every turn. The service runs only for the topic-triggered documents lane, identifier-like prompts (`scope=main`), the targeted entity lookup, an optional `promptServiceScope`, or as a `scope=main` fallback when native memory fails.
- Add a per-source quota for native results (`nativeRouting.sourceQuota`, default 3 notes + 2 session chunks): with both corpora configured, each is searched separately, then merged by score with free slots filled from leftovers, so session chunks cannot crowd out notes.
- Add native low-confidence disclosure via `nativeRouting.lowConfidenceMode`, default `off` because an absolute score does not separate no-match from correct hits once sessions are indexed: `score` (best score below `lowConfidenceScore`) or `lexical` (no query-term overlap and a weak score; both must agree). Neither rule is validated on a labelled no-match set. Native failures always add a fixed unavailable notice and never yield verified-absence receipts.
- Receipts accept the exact list of searched sources for routed searches. No behaviour changes while `nativeRouting.enabled` is unset or false.

## 1.13.0

- Preserve ordinary unified memory search when private facts are unauthorized or fail (including timeouts and malformed state). Prepend the facts-only unavailable notice, retain normal search parameters, formatting and receipts, and log the bounded reason code. Fallback requests use neither fact markers nor the facts bearer token and never emit fact state. Authorized successful recall and authorization rules are unchanged.
- Add privacy-safe internal reason diagnostics for owner-private fact hook recall, tool recall, proposals and confirmations. Only static stage/reason codes and allowlisted context-field presence booleans are logged; errors, URLs, credentials, prompts, fact values and identifiers are never logged.
- Dedupe identical session/stage/reason diagnostics for 60 seconds with bounded retention (256 entries). Authorization, external unavailable notices and fail-closed behavior are unchanged.
- Add reason-path, privacy, revalidation and dedupe regression coverage. No activation or configuration changes; installation after merge requires a plugin reload, not a Gateway restart.

## 1.12.0

- Add disabled-by-default Option C SecretRef-authenticated owner-private propose/confirm tools, lifecycle/forget drafts and automatic bounded current-fact recall. Agent-interpreted consent replaces unavailable inbound/delivery hooks; local authenticated requester profiles gate WebChat writes. Forwarding/consent residual risks and unsupported Telegram writes are documented. No deployment.

Release notes for tagged versions are also generated by the release workflow.
The package version is bumped in the release commit, not in feature branches.

## 1.11.0

### Added
- Topic-triggered document search: on eligible human turns a
  deterministic German/English/Russian lexicon detects family, home, vehicle,
  finance, insurance, school, work and health topics and starts a
  `scope=documents` lookup in parallel with the `scope=all` baseline. Baseline
  order of retained entries is preserved and `documentSlots` (default 2)
  distinct documents are reserved in the merged context; baseline documents
  are never evicted, low-ranked non-document entries may be replaced.
- `topicTrigger` plugin configuration: `enabled`, `documentSlots`, `timeoutMs`,
  `disabledCategories`, `extraTerms`, `entityAliases`. Entity aliases (family
  members, school, employer) come from configuration only; the default lexicon
  contains no personal names.
- A failed or timed-out documents lookup is soft: baseline context is kept and
  the fallback is disclosed (fixed notice; unverified coverage in receipts). If
  the baseline search fails first, the pending documents request is cancelled.
- `searchUnified` accepts an optional `{ signal }` to abort a request from the
  caller.

### Changed
- Triggered turns issue one additional request (documents scope, parallel,
  bounded by the existing timeout and six-second budget). Set
  `topicTrigger.enabled: false` to restore the previous single-request
  behavior.
- `npm run check` also syntax-checks `src/entity-query.js` and the new modules.

### Unchanged
- Internal turns (heartbeat, cron, memory flush, inter-session) and chats
  outside the configured allowlists never run recall (v1.10.0 behavior).
- The adapter timeout default and the six-second turn budget.
